# Searchtide 0.3 : modules — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** transformer les intégrations de Searchtide en modules activables par projet. Le projet devient l'objet central, avec un catalogue de KPI, des jalons et un fil « Aujourd'hui ».

**Architecture :** un registre de modules côté serveur (`server/modules/`) s'ajoute au registre de connecteurs existant, sans le remplacer. Deux tables gardent l'état (`modules`, `project_modules`). Les outils MCP, les blocs de page, les tâches de fond et les onglets ne sont exposés que pour les modules actifs. L'interface lit `/api/modules` et un registre côté client (`web/src/modules/`) pour construire le menu, les onglets et les blocs.

**Tech Stack :** Node 22.18 (type-stripping), Hono, `node:sqlite`, zod, `@modelcontextprotocol/server`, React 19, Vite, Tailwind v4, `node:test`, Playwright.

**Spec :** `docs/superpowers/specs/2026-11-10-modules-design.md`. À lire en entier avant toute tâche : les numéros § ci-dessous y renvoient.

## Global Constraints

- Aucune nouvelle dépendance (§3).
- Migrations uniquement par `migrate(name, sql)` (`server/migrations.ts`), additives, sans supprimer de colonne en 0.3 (§3).
- Les 215 tests unitaires (`npm test`) et les 10 parcours e2e (`npm run e2e`) restent verts après chaque tâche.
- Les connecteurs (`server/connectors/*`, `contract.ts`, le coffre) ne changent pas de contrat.
- Commentaires et textes de l'interface en français. Une étiquette nomme ce que l'utilisateur obtient, pas la technique (§11).
- Un chiffre non mesuré ne s'affiche jamais comme 0 : on affiche « — » ou l'invitation « Activer <module> » (§2, anti-objectifs).
- Aucune clé d'agent ne crée, ne modifie ni ne lit une connexion ou un secret (§5.7).
- Commits : message en français, terminé par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Commandes de test : `DATABASE_PATH=:memory: node --test server/<fichier>.test.ts` pour un fichier ; `npm test` pour tout ; `npm run typecheck`.

## Review Focus

1. **Module désactivé, données gardées.** Désactiver Stripe sur un projet qui a des indicateurs Stripe masque ces indicateurs. Les réactiver les retrouve avec leur historique intact (test dans la tâche 2).
2. **KPI calculé dont une opérande est supprimée.** La valeur devient absente (`null`) et `last_error` explique quelle opérande manque, sans exception dans la collecte (test dans la tâche 8).
3. **Anciennes adresses en favori.** `?site=exemple.com&tab=search`, `?view=connections` et `?view=portfolio` ouvrent l'équivalent dans la nouvelle navigation, au lieu d'une page vide (test e2e dans la tâche 12).
4. **Agent qui active un module sans connexion.** Une clé en lecture seule n'a pas l'outil. Une clé en écriture reçoit une erreur claire (« Connectez d'abord Google dans Modules ») quand la connexion manque (test dans la tâche 3).
5. **Migration rejouée ou interrompue.** Un second démarrage ne réactive pas un module que l'utilisateur a désactivé entre-temps. Une erreur au milieu de la migration laisse la base inchangée (test dans la tâche 2).
